# 阶段 2/6：多端同步与 PWA

依赖：阶段 1（#1）。开始前按 `AGENTS.md` 的"开始一个阶段"执行，共同约定见 `docs/SPEC.md`。分支名 `stage-2-sync`。

目标：同一账号在多台设备上打开，一端保存，其他端约 2 秒内看到；断网能继续编辑，联网后自动同步；冲突不丢数据；能安装为 PWA。

## 范围内

### 后端

- 三方合并：写入的 base_rev 与当前 rev 不一致时，从历史版本表取 base_rev 那一版做行级三方合并（diff3 自己实现或选库，记进 MEMORY.md）。
  - 改动不重叠：写入合并结果，返回新 rev 和合并后的全文，客户端用它替换本地内容。
  - 改动重叠：保留服务器版本，把客户端版本另存为冲突副本 `名称.conflict-<设备名>-<yyyyMMdd-HHmmss>.md`，返回 409 和冲突副本路径。
  - base_rev 对应的历史版本已被清理：按重叠处理。
  - 这会改变阶段 1 中 409 的含义：在 `docs/api.md` 里写清楚，并把阶段 1 中断言旧 409 行为的测试改成新行为。
- 历史版本保留：每篇约保留最近 50 版或 30 天，后台定期清理，限制数据库体积。
- 设备标识：写请求带 `X-Device-Id` 和设备名，服务器记录在变更事件里。
- WebSocket `/api/ws`（会话 cookie 鉴权）：推送 `{seq, type: upsert|move|delete, id, path, rev, deviceId}`，不推正文，客户端按需拉取；约 30 秒一次心跳。
- 增量接口 `GET /api/changes?since=<seq>`：返回之后的变更；seq 早于已清理的范围时返回 410，客户端改为全量重拉。
- fsnotify 发现的外部修改同样产生变更事件。

### 前端

- 同步引擎放在 `web/src/sync/`：
  - IndexedDB 缓存笔记树和打开过的笔记正文；
  - 写队列持久化到 IndexedDB：在线时立即发送，离线时入队，联网后（online 事件或 WebSocket 重连）按顺序重放；
  - 重连后先用 `since=seq` 补齐错过的变更；收到 410 需要全量重拉时，保留写队列，重拉完成后再按顺序重放，不能用服务器数据覆盖未同步的本地修改。
- 设备 id 首次启动时生成并存在 localStorage；设备名默认从 UA 推断，可在设置里改。
- 当前打开的笔记被其他设备改了：
  - 本地没有未保存改动：直接替换内容，按 diff 映射保持光标和滚动位置；
  - 本地有未保存改动：立即保存，由服务器合并，用返回结果更新；
  - 正在用输入法组字（composition）时推迟替换，组字结束后再处理，避免打断中文输入。
- 同步状态指示：已同步 / 同步中 / 离线（N 项待同步）/ 有冲突。产生冲突副本时弹 toast，点击可打开冲突副本。
- PWA：
  - manifest：名称、192 和 512 图标（含 maskable）、theme_color、`display: standalone`；
  - service worker 缓存应用壳；`/api` 请求不经 SW 缓存，由同步引擎负责；
  - 有新版本时提示"有新版本，点击刷新"；
  - iOS 补齐 apple-touch-icon 和状态栏 meta。
- 离线冷启动：断网时打开应用，能看到缓存的笔记树并编辑已缓存的笔记。

## 范围外

CRDT 和逐字实时协同、多人协作、冲突副本的可视化对比合并界面（可选扩展，有余力再做）、深度视觉打磨（阶段 3）、MCP、Agent。

## 集成约定

- 同步引擎是前端读写笔记的唯一入口，编辑器和文件树都通过它，不再直接调 `/api` 写接口。
- WebSocket 和增量接口的格式写进 `docs/api.md`，阶段 4 的 MCP 写入和阶段 5 的 Agent 写入复用同一套变更事件。

## 保持不变

- 除 409 的含义外，阶段 1 的 API 向后兼容。
- 文件为真相源；除上面说的 409 测试外，阶段 1 的测试原样通过。

## 验收标准

1. Go 单测覆盖：不重叠自动合并、重叠生成冲突副本、base 版本缺失、`changes?since` 正常返回和 410、历史版本清理。
2. Playwright 两个浏览器上下文 A、B 打开同一篇笔记：A 修改后，B 不刷新、在 2 秒内看到（测试超时设为 2 秒）。
3. Playwright 离线：B 断网（`context.setOffline(true)`）后编辑两篇笔记，状态显示"离线（2 项待同步）"；恢复网络后两篇都同步到服务器，A 也看到。
4. Playwright 冲突：A、B 基于同一 rev 改同一行，生成冲突副本且两端都有提示；A 改第 1 段、B 改第 3 段（中间隔着未改动的第 2 段）则自动合并、不产生副本，两端最终内容一致。
5. Playwright 检查 PWA：manifest 字段齐全，service worker 处于 active 状态；断网后 reload 仍能看到笔记树。
6. 沿用阶段 1 的笔记生成脚本和 RSS 测法：有 2 个 WebSocket 连接时，1000 篇笔记的空闲 RSS 仍 ≤ 50MB。
7. 在 `docs/dev-https.md` 写明如何在局域网用 HTTPS 访问开发服务（例如 Caddy 本地证书），供手机测试。
8. 写入 `docs/checklist/stage-2.md`：手机（Android Chrome、iOS Safari）安装到主屏 → 断网编辑 → 联网后电脑上看到；两台设备同时编辑同一篇时的体验。
