# 阶段 1/6：核心骨架与单机笔记

依赖：无。开始前按 `AGENTS.md` 的"开始一个阶段"执行，共同约定见 `docs/SPEC.md`。

本阶段从只有 LICENSE、README 和文档的仓库开始，搭出单机可用的笔记应用：Go 后端 + React 编辑器。分支名 `stage-1-core`。

## 开始顺序

1. 检查 go（需 ≥1.22）、node（≥20）、pnpm 版本；缺失就停下汇报。
2. 建分支，再开始实现。

## 范围内

- 仓库结构：`server/`、`web/`、`docs/`、`scripts/`，dev / build / test 各提供 ps1 和 sh 两个版本。
- 后端：
  - 配置、SQLite 迁移；
  - vault 存储与索引：FTS5 trigram、链接、标签、历史版本、seq；
  - 启动对账与 fsnotify；
  - 首启设密码、登录、登出、登录限速（约每分钟 5 次失败后锁定 1 分钟）；
  - 笔记工具层 `server/internal/notes` 与 REST `/api/*`。写接口已经接收 base_rev，不一致时返回 409（合并留到阶段 2）；
  - 附件上传、回收站；
  - `GET /api/health`；
  - 内嵌前端。
- 前端：
  - 首启页、登录页；
  - 三栏布局、文件树；
  - CodeMirror 实时预览编辑器；
  - 自动保存：编辑停顿约 500ms 后保存，显示"保存中 / 已保存 / 失败"状态；
  - wikilink 补全、反链面板、标签、搜索、快速切换器、回收站；
  - 亮暗主题。
- 设计 tokens：先加载 `apple-design` skill，按它建立颜色、字体、圆角、阴影、弹簧参数，放在 `web/src/styles/tokens`，后续阶段复用。本阶段做到"干净可用、风格方向正确"即可，深度打磨在阶段 3。

## 范围外

WebSocket 推送、三方合并、离线与 PWA、API token 及其管理界面、MCP、Agent、发布流水线、关系图谱。

## 集成约定

- 开发时 Vite 把 `/api` 代理到 Go 服务。
- API 写进 `docs/api.md`：路径、请求/响应 JSON、错误码。后续阶段在此基础上扩展。

## 保持不变

无（新项目）。

## 收尾

在 `AGENTS.md` 的"常用命令"里补全 dev / build / test 用法；推送分支并开 PR。

## 验收标准

1. `go test ./...`、`pnpm -C web test`、`pnpm -C web build` 全部通过。
2. Go 单测至少覆盖：链接解析、改名更新引用、外部改名保留 id、中文搜索（2 字和 4 字查询都能命中）、目录穿越被拒、旧 base_rev 返回 409。
3. 用构建出的单二进制启动后，能完成首启设密码和登录；连续输错密码会被限速。
4. Playwright 冒烟测试通过，覆盖：新建笔记 → 输入 → 显示"已保存" → 刷新后内容一致 → 磁盘上的 .md 文件内容一致 → 能搜到 → 删除进回收站 → 恢复。
5. 在外部修改 vault 里的 .md 文件，约 2 秒内反映到文件树和搜索结果。
6. 重命名笔记后，其他笔记里的 `[[旧名]]` 被更新，反链显示正确。
7. 用脚本生成 1000 篇笔记、重启并完成索引后，空闲 RSS ≤ 50MB；超出就报告实测值和主要占用来源。
8. 截图 4 张（桌面 / 375px 宽 × 亮 / 暗），存放在 `docs/screenshots/stage-1/`，按 3 级推送。
9. 需要人工上手操作的体验项（例如编辑手感、中文输入法下的自动保存）写入 `docs/checklist/stage-1.md`。
