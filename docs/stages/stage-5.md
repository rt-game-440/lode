# 阶段 5/6：Agent 助手

依赖：阶段 3（#3）、阶段 4（#4）。开始前按 `AGENTS.md` 的"开始一个阶段"执行，共同约定见 `docs/SPEC.md`。分支名 `stage-5-agent`。

目标：应用内置一个能读写笔记的 AI 助手；可以配置多个供应商的多个模型，每个模型单独设置上下文窗口、推理强度和输入模态。

## 开始顺序

1. 查 OpenAI（Chat Completions 和 Responses）、Anthropic Messages、Google Gemini 三家当前的官方文档：流式格式、工具调用格式、推理/思考参数、图片 / PDF / 音频输入方式、列出模型的接口。把"推理强度 off/low/medium/high → 各家参数"的映射表和依据链接写进 `docs/agent.md`。不要凭记忆写参数名。
2. 决定用官方 Go SDK 还是直接发 HTTP + 解析 SSE，记进 MEMORY.md。依赖少、二进制小优先。
3. 再开始实现。

## 范围内

### 供应商与模型管理（设置页）

- 供应商：名称、类型（OpenAI 兼容 / Anthropic / Gemini）、base URL、API key；"测试连接"按钮。
- API key 用 AES-GCM 加密存库，主密钥取自 `LODE_SECRET_KEY`。没设置这个环境变量时不允许保存 key，界面说明如何设置。接口永远不返回明文 key，只显示末 4 位。
- 模型：可从供应商的模型列表接口导入，也可手动添加。每个模型的字段：
  - 模型 ID、显示名、是否启用；
  - 上下文窗口（tokens）、最大输出（tokens）；
  - 推理强度：off / low / medium / high，按映射表转换；模型不支持时隐藏这一项；
  - 输入模态：text / image / pdf / audio 多选；
  - 是否支持工具调用；
  - temperature（可选）。
- 设一个默认模型。

### 适配层 `server/internal/llm`

- 统一接口：输入模型配置、消息（文本加附件）、工具定义；输出事件流：文本增量、思考增量、工具调用、用量、完成、错误。
- 取消：客户端断开或点"停止"时取消请求上下文，向供应商的请求随之中断。
- 错误要可读：鉴权失败、限流、上下文超长、模型不存在，分别给出提示。

### Agent 循环（服务端）

- 工具来自阶段 4 的注册表。只读工具自动执行。写工具（create / update / move / delete）先暂停，把带 diff 的待批准请求推给前端：批准后执行，拒绝后告诉模型"用户拒绝"。设置里可以打开"自动批准写操作"，默认关闭。
- 单轮最多约 20 次工具调用，超过就停下并告知用户。
- 上下文管理：可用预算 = 上下文窗口 − 最大输出 − 约 5% 余量。
  - token 数粗估：中日韩字符每个按 1 token，其余字符每 4 个按 1 token；有供应商计数接口时可选用；
  - 超出预算时，先截断过长的工具结果（保留开头并注明已截断），再用当前模型把较早的轮次压缩成摘要；
  - 系统提示和最近一轮始终保留。
- Agent 的写入走笔记工具层，产生变更事件，编辑器实时更新。
- 对话记录存 SQLite：会话列表、消息、使用的模型、用量。

### 界面

- 桌面在右栏加"助手"标签页；手机上为全屏页面。复用阶段 3 的组件和 tokens。
- 会话列表、新建会话、删除会话。
- 输入框：
  - 模型切换，可在本会话内覆盖推理强度；
  - "@当前笔记"标签默认带上，可以 @ 其他笔记；
  - 附件按钮只在模型支持对应模态时可用，否则置灰并说明原因；可以选 vault 里的图片。
- 消息区：
  - Markdown 流式渲染；
  - 思考内容默认折叠；
  - 工具调用卡片默认折叠，展开看参数和结果；
  - 写操作批准卡片显示 diff，带"批准 / 拒绝"；
  - 停止按钮；
  - 显示本会话已用 token / 上下文窗口。
- 服务端到前端用 SSE（`/api/agent/chats/{id}/stream`）。

## 范围外

向量检索和语义搜索、多 Agent、语音输入、图片生成、按会话计费统计（可选扩展）。

## 保持不变

MCP 工具的行为和描述不变（如需修改，同时验证 MCP 测试）；已有测试继续通过。

## 验收标准

1. Go 单测：每个适配器用 httptest 模拟的供应商流式响应（按官方格式手写或录制的样例）覆盖文本流、思考流、工具调用、错误和取消；推理强度映射表有表驱动测试。
2. Agent 循环测试：模拟模型先调 `search_notes`、再调 `update_note` → 停在待批准；批准后文件被修改，拒绝后文件不变。
3. 上下文测试：分别用中文和英文构造超过窗口的历史，最终发给适配器的请求按上面的估算方法 ≤ 可用预算，且系统提示和最近一轮完整保留。
4. 数据库里的 API key 不是明文；任何接口的响应里都没有明文 key；日志里不出现 key。
5. Playwright 用模拟的 OpenAI 兼容服务跑完整流程：添加供应商和模型 → 新建对话 → 流式回复出现 → 工具调用卡片 → 批准写入 → 编辑器内容更新。
6. 真实供应商冒烟：读取环境变量 `LODE_TEST_OPENAI_KEY`、`LODE_TEST_ANTHROPIC_KEY`、`LODE_TEST_GEMINI_KEY`，设置了的就跑一轮带工具调用的对话，没设置的跳过并在汇报中注明。
7. 3 级：录屏流式对话、切换模型、批准 diff 三个场景并推送。
8. 写入 `docs/checklist/stage-5.md`：用你自己的密钥配置至少两家供应商，试推理强度、图片输入和写入批准。
