# 性能基准

用 `server/cmd/bench` 测量。它对每个笔记数量依次：

1. 用 `cmd/gennotes` 在临时数据目录生成笔记（中英混合正文、标签、`[[链接]]`、分布在多级目录）；
2. 首次启动 `lode serve`（空数据库），从日志“索引就绪 … dur=”读出**全量索引耗时**，完成首次设置；
3. 重启服务（读出**重启对账耗时**），登录并保持 2 个 WebSocket 连接，空闲 15 秒后读取**常驻内存**（Linux 读 `/proc/<pid>/status` 的 VmRSS；Windows 读工作集）；
4. 发 200 次搜索请求（中文三字词、英文词、两个词组合、中文两字词轮换），统计 **p50 / p95**；
5. 对 200 篇不同的笔记各发一次保存请求（`PUT /api/notes/{id}`，正文追加一行），统计 **p50 / p95**。

延迟是客户端测得的往返时间（本机回环），包含 HTTP 和 JSON 开销。服务以默认配置运行，没有设置 `GOMEMLIMIT`。

```bash
scripts/build.sh
cd server && go run ./cmd/bench -bin ../bin/lode -n 1000,10000
```

## 结果

### Linux（GitHub Actions ubuntu-latest）

测试机：GitHub Actions ubuntu-latest（Ubuntu 26.04.1 LTS，linux/amd64），4 个逻辑 CPU（AMD EPYC 9V74），内存 15.6 GB，Go 1.26.10，测试时间 2026-11-07 12:05 UTC（CI 运行 42370806602，提交 57b21ef）

| 笔记数 | 首次全量索引 | 重启对账 | 空闲 RSS（2 个 WebSocket） | 搜索 p50 / p95 | 保存 p50 / p95 |
|---:|---:|---:|---:|---:|---:|
| 1000 | 700ms | 9ms | 21.7 MB | 7.0 ms / 9.4 ms | 1.5 ms / 16.6 ms |
| 10000 | 7.36s | 64ms | 22.0 MB | 34.8 ms / 47.9 ms | 1.6 ms / 17.4 ms |

CI 的“性能基准”任务每次运行都会把同样的表格写到任务摘要里。

### Windows（开发机）

测试机：Windows 10 专业工作站版（amd64），AMD Ryzen 5 9600X（6 核 12 线程），内存 47 GB，SSD（2TB），Go 1.27，测试时间 2026-11-07 19:43

| 笔记数 | 首次全量索引 | 重启对账 | 空闲 RSS（2 个 WebSocket） | 搜索 p50 / p95 | 保存 p50 / p95 |
|---:|---:|---:|---:|---:|---:|
| 1000 | 595ms | 10ms | 25.2 MB | 5.9 ms / 7.1 ms | 3.6 ms / 14.9 ms |
| 10000 | 6.25s | 95ms | 22.8 MB | 46.5 ms / 54.4 ms | 3.6 ms / 20.6 ms |

Windows 会定期修剪空闲进程的工作集，所以空闲 15 秒后的数值偏低，10000 篇甚至比 1000 篇少；以 Linux 的 RSS 为准。

## 结论

- **达标**：目标是 1000 篇空闲 RSS ≤ 50MB、10000 篇约 ≤ 120MB；Linux 实测 21.7MB 和 22.0MB。
- 内存基本不随笔记数增长：笔记正文不常驻内存，全文索引（SQLite FTS5 trigram）在数据库文件里，SQLite 每个连接的页缓存限制在约 2MB；索引完成后服务会调用 `debug.FreeOSMemory()` 把建索引时的临时内存还给系统。
- 搜索延迟随笔记数线性增长：三个字符以上的词走 FTS5 trigram 再按 bm25 排序，两个字的中文词（如“性能”）只能用 LIKE 扫描正文，是 p95 的主要来源。10000 篇时 p95 在 50ms 左右，交互上感觉不到。笔记数再增加一个数量级时，可以给两字词加 bigram 索引。
- 保存延迟与笔记数无关，主要是写文件、更新索引和 SQLite 事务提交（WAL）；p95 的长尾推测来自偶发的 WAL checkpoint 和磁盘同步。
- 首次全量索引 10000 篇约 6 秒，只在第一次导入时发生；之后启动只对比文件的修改时间和大小，10000 篇不到 0.1 秒。
