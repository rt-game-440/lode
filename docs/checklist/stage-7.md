# 阶段 7 人工验收清单

准备：

- 一个已有的 Obsidian 库（有几篇笔记、至少一个子文件夹；用自己真实的库时，先复制一份当测试用，或确认已备份）。
- 电脑上装好 Obsidian，Lode 跑在同一台电脑上（`scripts/dev.sh`，或 `scripts/build.sh` 后 `bin/lode serve`），浏览器打开 Lode 并登录。
- 下面的“库路径”指这个 Obsidian 库在电脑上的绝对路径，例如 `D:\笔记\我的库`。

说明：本清单只覆盖需要人上手操作的部分（#60 外部目录、#64 手机 PWA）。第 1–4 条需要电脑，第 5–7 条用手机，已安装为 PWA（局域网 HTTPS 见 `docs/dev-https.md`，或用已部署的实例）。路径校验、对账、监听、删除不动外部文件等已有自动化测试（`internal/workspace/external_test.go`、`web/e2e/ui-workspace-external.spec.ts`）。

- [ ] **1. 把已有的 Obsidian 库接入为外部工作空间**
  - 操作：
    1. 侧栏顶部点工作空间名 → “新建工作空间…”，名称填“我的 Obsidian 库”，打开“使用已有文件夹”，路径填库路径，点“接入”。
    2. 在 Lode 里浏览文件树，打开几篇笔记；用搜索找一个库里的关键词；点开一篇带 `[[双链]]` 的笔记，看反链。
    3. 打开库所在的文件夹（资源管理器 / 访达），确认里面没有多出文件或文件夹（只有你自己的内容和 Obsidian 自己的 `.obsidian/`）。
  - 预期效果：创建后自动切到这个工作空间，库里的笔记（包括子文件夹里的）都出现在文件树里，搜索、标签、反链可用；库文件夹里没有任何 Lode 产生的文件（索引、回收站、锁文件都在 Lode 数据目录的 `workspaces/<id>/` 下）。
  - 用户反馈：

- [ ] **2. 在 Obsidian 和 Lode 里交叉编辑**
  - 操作：
    1. 用 Obsidian 打开同一个库。在 Obsidian 里新建一篇“来自 Obsidian”的笔记，写几行字，再改一篇已有笔记的标题和正文。
    2. 回到 Lode 的浏览器页，不刷新页面，观察文件树和正在打开的笔记。
    3. 在 Lode 里改另一篇笔记（加一行字），新建一篇“来自 Lode”的笔记，把“来自 Obsidian”那篇移到一个子文件夹，再删除一篇不要紧的笔记。
    4. 回到 Obsidian，观察文件列表和各篇内容；在 Obsidian 里重命名一篇被别的笔记 `[[链接]]` 引用的笔记。
    5. 在 Lode 的“回收站”里恢复第 3 步删除的那篇，回到 Obsidian 看它是否回来。
  - 预期效果：
    - 第 2 步：新笔记和改动在一两秒内出现在 Lode，打开着的笔记内容跟着更新（没有未保存修改时）。
    - 第 3、4 步：Lode 里的新建、修改、移动、删除一两秒内反映到 Obsidian 的文件列表；Obsidian 不弹出“文件已被外部修改”之外的异常提示，库里的 `.obsidian/` 配置没有被改动。
    - 第 4 步：Lode 里被重命名的笔记，引用它的笔记仍能点开。
    - 第 5 步：恢复的笔记回到原路径，Obsidian 里重新出现。
    - 全程库文件夹里没有出现 `.trash`（Lode 的回收站不在库里；Obsidian 自己删除时放进的 `.trash` 不算）、临时文件或 Lode 的其他文件。
  - 用户反馈：

- [ ] **3. 删除外部工作空间不会删除笔记文件**
  - 操作：
    1. 记下库文件夹里的文件数量（或在资源管理器里按“修改时间”留意一下最近的文件）。
    2. “设置 → 工作空间”→ 点这个工作空间 → “删除工作空间…”，读确认框的文字，点“删除”。
    3. 查看库文件夹，用 Obsidian 重新打开这个库。
    4. 用同样的路径再接入一次。
  - 预期效果：确认框明确写着“不会删除你的笔记文件”；删除后库文件夹里的所有笔记、附件、`.obsidian/` 原样都在，Obsidian 能正常打开；再次接入后笔记全部重新出现（工作空间 id 是新的，之前在 Lode 里删进回收站的笔记不在了，它们在数据目录的 `trash-workspaces/` 里）。
  - 用户反馈：

- [ ] **4. 命令行管理（可选，需要能停服务）**
  - 操作：
    1. 服务运行中执行 `bin/lode workspace list`。
    2. 停止服务，执行 `bin/lode workspace list`、`bin/lode workspace add 命令行加的 --dir <另一个测试文件夹的绝对路径>`、`bin/lode workspace rename <id> 新名字`、`bin/lode workspace remove <id>`，每步之后再 `list`。
    3. 试一下错误输入：`--dir` 填相对路径、不存在的路径、数据目录本身。
    4. 重新启动服务，在设置页看工作空间列表。
  - 预期效果：第 1 步报“lode 服务正在运行”并以非零状态退出；停服后各命令成功，`list` 的结果与设置页一致；错误输入时给出各自不同的中文原因，不会登记；重启后设置页里能看到命令行加的空间，删除后不再出现。
  - 用户反馈：

- [ ] **5. 在手机 PWA 上切换工作空间**
  - 操作：
    1. 手机上打开已安装的 Lode PWA 并登录，回到文件列表（笔记列表页）。
    2. 点左上角的“笔记”（工作空间名）→ 在列表里点“新建工作空间…”，名称填“手机测试”，点创建。
    3. 在新空间里新建一篇笔记，写几个字。
    4. 再点左上角的工作空间名，切回“笔记”（默认空间），确认看不到刚写的笔记；再切到“手机测试”，确认笔记还在。
    5. 在“手机测试”里把手机切到飞行模式，再改一篇笔记；切回默认空间，关闭飞行模式，再切回“手机测试”。
    6. 用电脑浏览器登录同一个实例，切到“手机测试”，看笔记是否同步过来。
    7. 完全关闭 PWA 再重新打开。
  - 预期效果：切换器菜单触摸目标够大、不遮挡内容，当前空间打勾；切换后文件树、搜索和最近打开都只显示该空间的内容，不会串；离线时的修改在恢复网络并回到该空间后补发，电脑上看得到；重新打开 PWA 后仍停在上次所在的空间（地址是 `/w/<id>/...`），没有白屏或闪烁。
  - 用户反馈：

- [ ] **6. 手机上管理工作空间并删除一个空间**
  - 操作：
    1. 手机上“设置 → 工作空间”，进入“手机测试”，改名为“手机测试2”，回到列表确认；再用拖动把手调整顺序。
    2. 回到侧栏打开切换器，确认名称和顺序已更新。
    3. 在“手机测试2”里（当前所在空间）进入“设置 → 工作空间 → 手机测试2 → 删除工作空间…”，读确认框文字，点“删除”。
  - 预期效果：改名和排序即时反映在切换器里；拖动手势不会同时滚动页面；确认框说明会回到默认空间、内置空间的目录只是移到数据目录的 `trash-workspaces/` 而不是直接删除；删除后自动回到默认空间，切换器里不再有这个空间，没有错误提示或白屏。
  - 用户反馈：

- [ ] **7. 创建绑定工作空间的 MCP token（可选）**
  - 操作：
    1. 在“设置 → API token”创建 token，工作空间下拉选“笔记”以外的一个空间。
    2. 用 `docs/mcp.md` 里的 curl 示例带这个 token 调 `search`。
    3. 回到设置页删除该工作空间，再用同一个 token 调一次。
  - 预期效果：搜索结果只来自绑定的那个工作空间；删除工作空间后同一个 token 返回 401。
  - 用户反馈：
