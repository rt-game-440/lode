- [x] **11. 加密助手 API key 需要比 `LODE_SECRET_KEY` 更方便的机制**（2026-11-08，建议）
  - 现状：要保存供应商 API key，必须先自己生成一个 32 字节的主密钥，设置环境变量 `LODE_SECRET_KEY` 再启动；不设置就不能保存 key，设置错了或换了，已存的 key 全部失效。普通用户很难理解，也容易漏掉。
  - 预期：默认情况下不需要任何手动配置就能安全地保存 key，`LODE_SECRET_KEY` 只作为进阶选项保留（设置后优先使用，兼容现有部署）。
  - 可选方案（修复前和用户确定）：
    - A. 首次需要时自动生成主密钥，存成数据目录里的 `secret.key`（仅所有者可读）。零配置，Docker 卷、二进制部署都适用。代价：拿到数据目录就能解密，所以备份要决定是否包含它——包含则恢复即用，不包含则恢复后需要重新填 key；
    - B. 用登录密码派生主密钥（Argon2id），登录时解锁并只保存在内存里。数据目录泄露也解不开；代价是服务重启后要有人登录一次助手才能用 key，改密码要重新加密，`reset-password` 会让已存的 key 失效；
    - C. 使用系统钥匙串（Windows DPAPI、macOS 钥匙串、Linux Secret Service）。桌面上体验好，但 Docker 和无桌面的服务器上不可用，只能作为 A 的补充。
    - D. 用通行密钥保护（WebAuthn PRF 扩展）：用通行密钥验证时由浏览器派生一段密钥材料，用它包裹主密钥；每个登记的通行密钥各包一份，手机和电脑可以分别登记。服务器上不保存能解开 key 的东西；代价同 B：需要 HTTPS，服务重启后要有人用通行密钥登录一次助手才能用 key（例如无人登录时经 MCP 触发的助手调用拿不到 key），通行密钥全部丢失后要重新填 API key（笔记不受影响）。各平台对 PRF 的支持情况（Google 密码管理器、iCloud 钥匙串、Windows Hello 等）修复前要先核实。
  - 用户决定（2026-11-08）：A 作为默认，备份里默认包含 `secret.key`，并在设置页和文档里说明“备份文件等同于含有你的 API key，请妥善保管”；D 作为设置里可选开启的“用通行密钥保护 API key”；`LODE_SECRET_KEY` 继续作为进阶选项保留。
  - 修复：已合并（PR #32、#42，ticket #27、#29），人工验收见文末

  - 现象：目前看目录只能打开右栏的“大纲”标签，要占用一整栏。用户参考的是正文右侧一列细横线组成的目录条：每条线对应一个标题，缩进和长短表示层级，当前阅读位置的那条加深；鼠标移上去在原位置浮出完整目录卡片（标题文字、层级缩进、当前项高亮、内容多时可滚动）。参考截图：`docs/screenshots/issues/19-toc-rail-collapsed.png`（收起）、`docs/screenshots/issues/19-toc-rail-hover.png`（悬停展开）。

- [ ] **20. 移动端笔记页的助手底部面板在半屏时显示不全，必须拉到全屏才能看到最新消息和输入框**（2026-11-08）
  - 现象：手机上在笔记页打开助手（底部面板），面板停在半屏高度时，会话记录的下半部分和底部输入框都在屏幕之外：看不到最新的回复，也看不到、点不到输入框，滚动也到不了底。把面板拉到全屏后才完整显示（最新消息和输入框都在）。截图：`docs/screenshots/issues/20-agent-sheet-half.png`（半屏，最新回复和输入框被截掉）、`docs/screenshots/issues/20-agent-sheet-full.png`（全屏，显示完整）。
  - 推测：面板内容区按全屏高度布局，半屏只是把面板整体往下平移，超出屏幕的部分被裁掉，而不是让内容区高度跟随面板可见高度。
  - 预期：任何吸附高度（半屏、全屏）以及拖拽过程中，输入框都贴在面板可见区域的底部，会话列表占据剩余空间并可滚动到最新消息；新消息到来时自动滚到底；软键盘弹出时输入框在键盘上方。底部面板来自上一轮的 ticket #20（PR #40）。

- [ ] **21. 发送一轮消息后，输入框总会自动重新附上一篇笔记，无法保持“不附笔记”**（2026-11-08）
  - 现象：在笔记页的助手里，用户不想附任何笔记，把附件标签去掉后发送消息；这一轮发送完，输入框里又自动出现一个笔记标签（例如当前笔记“读三国演义有感”），下一条消息如果不手动删掉就会带上它。截图：`docs/screenshots/issues/21-auto-attached-note.png`。
  - 预期：附上笔记由用户决定。用户在本次会话里移除了自动附上的笔记后，后续轮次不再自动附上（直到切换到另一篇笔记或新建会话）；已经在之前消息里附过的笔记，后续轮次不重复附上。如果保留“附上当前笔记”的便捷入口，用未选中的虚线建议标签（截图 16 中的样式）表示，点一下才附上，而不是直接变成已附上的实线标签。需要核实触发重新附上的具体时机（发送后、回复结束后、还是笔记保存 / 重命名后）。

- [ ] **22. 助手输入框的模型切换下拉很粗糙，改成更优雅的选择器**（2026-11-08）

  - 预期：换成与应用一致的自定义选择器：收起时是一个轻量的文字按钮（显示模型显示名，没有显示名时显示简短 ID，配一个小的展开箭头，无底色或仅悬停时有底色）；点击后弹出应用风格的菜单（与“更多操作”菜单同一套组件和圆角、阴影），按供应商分组列出可用模型，当前项打勾，每项可附带简短能力提示（如推理、图片）；如果模型支持推理，推理强度也可以在同一菜单里切换。键盘可操作（↑↓、Enter、Esc），手机端以底部面板或贴近按钮的菜单呈现。和第 15、16、21 条一起改助手输入框。

- [ ] **23. 可以调整应用整体的字体大小**（2026-11-08，建议）
  - 现象：界面和正文的字号固定，无法按个人习惯或屏幕调大调小。
  - 预期：在“设置 → 通用”里提供整体字号调节（例如 5 档滑块或“小 / 标准 / 大 / 特大”，带实时预览），同时影响界面（侧栏、菜单、设置、助手）和笔记正文，布局随字号伸缩不错位、不截断；设置按设备保存（手机和电脑可以不同）。尊重浏览器 / 系统的默认字号（以 rem 为基准缩放），并保留浏览器自身缩放。和第 18 条的按笔记字体可以叠加：整体字号决定基准大小，单篇笔记只换字体。
